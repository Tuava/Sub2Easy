# v0.5.0 · 并行任务处理

## 使用

任务中心 → 并行任务池：

- 同时处理账号：默认 3，可选 1–8。
- 同时授权上限：默认 2，可选 1–8；实际不会超过正在运行的任务数。
- 暂停新任务：停止领取排队任务，当前请求继续到检查点，不删除队列。
- 保存即生效，不需重启。降低上限不会强杀已有任务；释放到新上限后继续领取。

这两个本地任务上限与导入模板中的 **sub2api 账号业务并发数** 是不同配置。

## 执行与一致性

- 独立分发线程 + 有界 ThreadPoolExecutor + 独立监控线程。授权、导入上线、401修复、续跑共用任务池。
- 在容量可用时才从SQLite领取任务，不预先把整个队列改成 running。
- SQLite事务与 pending唯一索引避免重复领取；额外按本地账号ID、登录身份、原站点/云端ID保留占用，直至处理函数完全返回。
- 网络等待不持有SQLite事务。工作线程不占用全局操作锁；前台入库、任务读取、取消、用量采集与监控列表读取可继续。
- 监控轮询自身互斥；重复“立即检查”复用当前轮询状态，不重复请求全站列表。对单账号做决策时使用协调锁，跳过占用中或读取期间更新的账号，避免旧401快照覆盖新恢复结果。
- 旧检查点续跑与绑定操作仍会短暂占用协调锁做身份/版本核对；并不是取消一致性检查。
- NVT名额等待可取消，真正发送前检查连接器和任务开关。等待授权名额时不提前写“已发送授权”的未知结果日志。
- Cookie失效/限流暂停连接器；旧失败响应不能覆盖新Key/Cookie。
- 有任务执行时不允许切换站点、管理员Key或锁库。可暂停领取、等待运行任务结束，再修改连接。
- 退出时先停止新领取与监控，等待所有已领取任务结束，再关闭凭据库。
- 默认主密码不持久化，进程重启后仍需解锁。升级可加 `--reuse-session` 保留私有启动文件里的本机会话令牌，避免旧标签页失效；不等于保留解锁状态。

## API

`GET /api/state` 新增 `task_pool.config` 和 `task_pool.runtime`（active、authorizing、queued、running、last_error、stopping）。

`POST /api/tasks/config`：

```json
{"max_workers":3,"max_authorizations":2,"paused":false}
```

仍要求本地会话令牌与解锁状态。

## 验证

- 实际线程事件阻塞测试证明两个账号同时进入授权处理函数。
- NVT上限、等待取消、暂停领取、同云端ID互斥、工作线程异常隔离。
- 运行时API可读、可入库、可刷新监控；改连接和锁库有明确错误。
- 独立监控在线程池忙碌时继续运行；过期401快照不能覆盖新恢复状态。
- 关停等待在途任务；配置跨锁库/解锁保留。
- UI实时计数、并发设置提交、轮询不覆盖未保存选择。

以上为本地测试，不通过多次调用真实NVT来制造并发，也不以测试替代真实账号的SSE验号和最终读回。
