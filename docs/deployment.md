# v0.3.0 · 本地账号一键导入服务器

## 实际入口

v0.4.1 增加首选入口：“批量导入”页直接填材料并点“导入到服务器并上线”，保存本地和服务器入队在一次提交完成，进度仍留在本页。下列号池入口继续用于已有库存，不再要求新导入用户切页操作。详见 `docs/inline-import.md`。

1. 先在“连接与模板”保存站点、管理员 Key，从下拉框选择隔离组/生产组/代理，保存模板。
2. 把三段账号材料保存到本地。已经保存的账号不用再导入。
3. 在号池勾选账号，点 **“导入服务器并上线”**，或点击单号的 **“导入服务器”**。
4. 确认本次站点和新号模板，填写可用的文本验号模型；新号需要确认隔离组不会被生产流量选中。
5. 一次确认后，由任务池跨账号并行执行，每个账号内部串行执行整条链。去 **“任务中心”** 看每个账号的具体阶段和最终结果。

侧栏版本来自 `/api/status` 的运行后端，不是静态写死的版本号。v0.3.0 返回 `server_deploy` 能力，表示后台确实加载了新任务类型。

## 行为

- 已有未过期的有效授权：复用本地加密结果，不需要 NVT Cookie，也不重新登录。
- 未授权/凭据过期：调用一次 NVT 获取凭据。响应必须通过邮箱、workspace、已知 user_id、有效期检查；个人免费空间回退仍然拒绝替换团队账号。
- 新号：读取完整账号列表检查同邮箱/确定性名称重复 → 校验组/代理 → 创建到隔离组 → 保存返回的 cloud ID → 停调度 → 验号 → 更新生产组 → 再次验号 → 启用 → 读回。
- 已绑定号：核对原绑定身份 → 停调度 → 获取或复用授权 → 更新原账号 credentials → 验号 → 启用 → 读回。原分组、代理、指纹、倍率、并发、优先级不被新号模板覆盖。
- 已绑定 `inactive`、正在维护、带有未完成修复/未知写入记录的账号不会被这个入口覆盖，需先处理原恢复任务。
- 发现云端已有同邮箱/同创建标识的未绑定账号时，停止创建并提示先批量绑定，不自动制造重复号。

新账号创建 API 默认可调度，不能把“创建后很快停用”称为原子隔离。创建前必须有已验证的隔离分组；程序校验分组存在，但不能仅根据组名称证明没有生产路由/fallback 使用它。

## 配置与快照

新任务使用**本次确认的当前模板快照**，让旧本地库存也能用刚配置好的真实组/代理，而不是永远绑着早期示例 ID。重试继续使用第一次部署的快照，不随新模板修改。已绑定号不应用该新号模板。

任务固定站点地址、连接修订、材料版本和本地绑定。换站点/改Key/改绑定后旧任务不会发送到新目标。

创建后逐字段核对云端分组、代理、并发、优先级、倍率、运营到期和指纹模式。已有号以初始云端配置摘要为基线；暂停后的 updated_at 和后续更新要一致。验号成功后还要检查限流/冷却、运营到期及配置漂移。最后必须读回 active、schedulable=true，新号还需生产组一致，才能显示“已导入并上线”。

上游测试接口有恢复运行态的副作用，不是纯只读探测。必须收到完整 SSE `test_complete + success=true`，HTTP 200/断流/错误事件均不能标成功。每个新号通常调用两次模型测试（隔离组一次、移组后一次），会产生用量。

## 失败与重试

每个变更请求先保存加密意图、阶段、请求标识，再调用远端。不将密码、Cookie、Token 写入任务错误说明或页面。

- 逐账号入队，单号失败不会取消批次中其他账号。
- `failed` 且前一步结果明确：重新点同一个入口续跑。已创建 ID 保留；验号失败后重试不重新建号、不会再获取一次已存在的授权。
- POST/PUT 响应丢失、进程在变更请求中途退出：`unknown`，不盲目重放。已获得 cloud ID 时尽早保存；未获得 ID 的创建超时不得再次新建。
- 原始响应身份不符：`review`，加密保留材料，不移组、不上线。
- 请求取消或程序停止发生在已发请求期间时无法撤回远端请求；重启不自动重发 running 任务。
- 验号过期的“移组/启用”重试会重新验号；如果配置发生外部变化则停止，不覆盖人工编辑。
- 完成的部署再次提交只返回“已完成”，不会再建号。当前尚未实现通用未知写入自动对账，此类记录仍需核对。

服务器导入任务与同账号的手动授权/401恢复共用唯一在途任务约束；未完成部署时监控不抢写该号。不会因为部署成功就偷偷开启逐号监控；已托管旧号完成部署后恢复原监控关系。
