# 同 UID / workspace 已存在时，更新原账号（v0.7.1）

## 区分身份与凭据

- access_token / refresh_token 是可轮换的凭据，不是账号主键。
- 本工具的身份检查使用 OpenAI OAuth 的邮箱、`chatgpt_account_id`（workspace）和可用的 `chatgpt_user_id`。
- 上游不同版本对“UID”的称呼可能不同。仅一条“UID已存在”的字符串不能证明某个候选身份正确，不能据此伪造/替换UID。

## 用户操作

1. 导入包含新Token的 sub2 JSON，勾选 **更新同身份账号凭据**。
2. 只存本地不修改云端；点 **导入到服务器并上线** 才创建更新任务。
3. 已有本地绑定：更新原云端ID，不重新创建账号。
4. 未绑定：全站读取候选，用完整身份找唯一原账号，详情读回再次核对，保存绑定后转为原账号更新。
5. 多个候选、占用、不同workspace或不同用户：显示候选列表，在绑定处理中心选择。人工选择仍需身份一致；选择后原导入批次可以重试。

TXT 只有邮箱/密码/2FA，没有可靠workspace信息。发现云端已有账号时，不凭邮箱/名称猜团队空间：先选择已有账号或补入新JSON，再继续。

## 后端流程

唯一原账号绑定 → 检查当前状态/配置 → 停调度 → 应用新凭据到原ID → 读回确认实际凭据 → SSE完整成功 → 开调度 → 最终读回。

- 保留原云端分组、代理、倍率、优先级、并发和指纹配置。新账号模板不用于覆盖旧账号。
- 有有效新凭据时不调用NVT；本地只是缓存且未应用时，401监控不会另发登录覆盖这份材料。
- 原deployment完成但新授权已导入：创建新的更新任务，不返回旧“already_complete”。旧任务留存，新的deployment记录关联前一次ID。
- 重复导入已经成功应用的同份凭据：库内HMAC摘要识别并跳过，不对UI公开摘要或Token。
- 新号创建前再次检查：授权期间云端出现唯一同身份账号，转为更新该账号，不重复创建。
- 绑定与任务状态转换原子保存；运行任务新增云端ID占用，避免另一线程同时操作该ID。

## 失败记录

- 已知的验证码/登录失败或401验号失败，且存在确认暂停和配置基线时，可显式补入同身份新凭据。旧恢复证据仍加密保留，新更新前必须再次核对原基线；人工改组/改代理或恢复调度不会被静默覆盖。
- 未知创建/写入、超时结果不明、已清理到测试组、进行中的任务，不因导入新JSON自动清除。
- 已返回未知写入结果的POST，即使后来看到“UID存在”，也不自动重新POST。应核对云端实际账号和原记录；本版没有通用未知创建对账向导。
- 团队→个人workspace回退不是同身份更新，仍按已有终止修复规则处理。
- 原账号被设为inactive、云端绑定失踪或身份冲突，不自动创建替代账号。

测试只使用虚构材料和模拟上游；不对任何生产账号的更新结果作保证。
