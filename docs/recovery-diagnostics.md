# 自动救号诊断与再次401处理

## 判断原则

恢复成功必须同时确认原绑定身份、新凭据、SSE完整成功和最终云端调度状态。服务返回个人免费 workspace 不代表原团队资格恢复；配置/版本与旧检查点不符时也不能强制覆盖。以下为通用错误处理规则，不包含真实账号操作记录。

## 新的自动分支

模型测试 handler 返回 `API returned <status>:` 的 SSE error 时，本地只提取固定状态码，不保存/展示整段上游正文：

| 状态 | 结果 |
|---|---|
| 401 | `PROBE_AUTH_401`：读回同一绑定账号、明确401、仍暂停、配置摘要未变且凭据写入已确认时，安排一次自动再次重授权 |
| 403 | `PROBE_ACCESS_DENIED`：权限/访问问题，不当作401重复登录 |
| 429 | `PROBE_RATE_LIMITED`：限流/配额，不通过重复登录清限流 |
| 502/503/504 | `PROBE_UPSTREAM_UNAVAILABLE`：不将上游异常冒充登录失败 |
| 无可识别结构 | 保留 `PROBE_FAILED`，不凭任意正文中的数字启动重登 |

401 再授权保留原绑定和配置摘要，持久化到期时间、配置代次、材料修订和原恢复调度意图。等待窗口过后后台自动派发，不需要站长点续跑。每次恢复链最多追加一次，仍受每账号30分钟2次登录预算和全局小时预算限制。若再次重授权后的验号仍然401，显示 `REAUTH_STILL_UNAUTHORIZED` 并停止，不形成无限循环。

Cookie 暂停时保留这份自动任务，显示“等待连接器恢复”；账号改了代理/分组/身份、被人工启停、配置代次变化，则停止旧任务。网络结果未知、响应身份不一致、未知写入结果不进入自动重登分支。

## Workspace 诊断

响应同一邮箱、同一稳定用户ID，但 workspace 与原绑定不同：

- `workspace_selection_kind=personal` 且 `plan_type=free` → `EXPECTED_WORKSPACE_NOT_RETURNED`，界面显示“团队授权未恢复”。
- 其他 workspace → `REAUTH_WORKSPACE_CHANGED`。
- 用户ID/邮箱不同 → 仍为身份不一致，不称为个人回退。

这三种结果都加密保留原响应，不替换原凭据，不把目标 workspace 改成返回的新值以凑过测试。手动授权的失败原因也同步显示到账号监控，避免监控仍停留在上一条泛化错误。

## 验证边界

静态页面更新和后端新版本加载是两件事，更新后请以 `/api/status` 的版本为准。测试使用虚构凭据、临时数据库及本地HTTP；不以模拟通过证明真实团队workspace已恢复。
