# v0.6.0 开源准备自查报告

## 本轮修复

| 项目 | 发现 | 处理 |
|---|---|---|
| 自动清理默认值 | 新安装未配置也会自动识别测试组并变更云端 | 改为默认关闭，开启需要移组确认与当前站点修订；测试覆盖 |
| 安装版数据目录 | 原默认路径依赖源码相对位置，wheel 安装可能写进 Python 环境 | 改用用户数据目录；已有源码数据目录继续沿用，启动脚本明确传目录 |
| 私有启动文件 | 直接 write_text 可能跟随符号链接或保留旧文件宽权限 | 原子替换，0600；进程锁拒绝符号/硬链接 |
| 应用退出 | lifespan yield 异常可能跳过正常清理 | try/finally 停止线程、等待任务、关闭数据库 |
| 文档 | 包含私有运营个案、过时串行和预算描述 | 移除个案ID、重写当前行为，历史提案标注非实现规范 |
| 公开打包 | 无许可证/CI/明确源码导出界限 | MIT候选、第三方说明、只读CI、显式打包/导出允许列表与包内扫描 |
| 初装验证 | 源码测试不证明 wheel 可独立运行 | 干净虚拟环境安装，临时 HOME，真实HTTP启动及锁库测试 |

## 本地验证结果

- macOS：Python 3.11 / 3.13 各 **477 项 Python 测试通过**。
- **25 项 jsdom 动态交互测试通过**。
- 编译检查与 Python wheel/sdist 构建通过。
- 安装 wheel 到独立虚拟环境，从源码目录外启动；首页/静态资源入口、会话校验、创建/解锁/锁库与新装空配置通过。未访问生产账号。
- Python `pip-audit` 对锁定运行依赖未报告已知漏洞；npm audit 报告 0 个漏洞（查询时点结果）。
- 允许列表源码、wheel、sdist 的模式检查无发现。压缩包没有账号库、启动令牌文件、运行日志、导出账号材料或个人环境目录。
- GitHub workflow YAML 可解析，Actions 引用为已查询的固定 commit SHA，权限为 contents:read；未使用生产 secrets。

## 尚未证明 / 发布者需确认

- 未创建 GitHub 仓库、未推送、未发布 PyPI；远端 CI 尚未执行，Linux 实机验证留给配置好的CI。
- MIT 是当前选择，发布者仍需确认权利归属；上游 sub2api 为独立第三方项目，接口兼容性研究不等于可重新许可其源码。
- 配置规则扫描和依赖漏洞库不是完整安全审计保证，发布前仍须审查 staged diff 与产物。
- 测试不证明任何真实账号恢复成功；上游API版本差异、无CAS竞态、接口费用/资格均有边界。
- 仍未实现 Windows 原生支持、通知、备用池补位、密码轮换与自动备份恢复；没有为了开源自查改动生产库或重启在用服务。

## 建议发布入口

使用 `scripts/export_source.py` 输出的 `sub2easy-0.6.0-github-source.zip` 解压到新目录，再初始化 Git。不要上传运营目录整个文件夹，也不要把旧版本 dist 文件一并发布。
