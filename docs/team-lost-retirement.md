# v0.5.3 · 团队授权丢失账号清理

按运营者要求，把 `EXPECTED_WORKSPACE_NOT_RETURNED`（同用户、个人免费 workspace 回退）视为终止自动修复条件。这是本站的运营处置规则，不代表对上游账号永久无法恢复作出判断。

## 开启规则

v0.6.0 起新安装默认关闭。先在账号监控页选择当前站点的测试组，确认移组并保存；已有明确保存且绑定站点的配置继续保留；旧版仅依赖隐式默认开启、未保存配置的安装升级后须重新确认开启。

## 自动流程

1. 检测处于 review/failed 的精确错误码，且绑定当前站点；旧诊断不改变已经恢复 active 的账号。
2. 退出自动重登、取消尚未执行的自动恢复；不重新授权，不写入个人 workspace 凭据。
3. 自动匹配唯一名称“测试组”的可用 OpenAI 分组。缺失/重名时不猜测，不改成隔离组；在账号监控页选择实际目标组。
4. 同任务池创建 retire 任务：身份检查 → 停调度并读回 → 仅将 group_ids 改为测试组 → 再次读回确认。
5. 确认只有测试组、schedulable=false、原绑定身份与凭据不变，才设为 retired；不启用、不验号、不再自动重登。
6. 保留登录材料、失败原始响应、原生产组信息与任务证据，不删除账号。完成后从监控清单与需要处理计数移除，可用“已移测试组”筛选查看。

## 失败边界

- 错用户、普通401、网络错误、`REAUTH_WORKSPACE_CHANGED` 不适用。
- 原写入结果未知、身份冲突、处理中任务、人工并发修改，不覆盖。
- 目标组读取失败允许下次读取；确认发出过云端写入后结果不明，不盲目重发。
- 清理失败仍显示“清理未完成”，不能假报移组成功。队列暂停和取消仍有效。
- 清理不依赖 NVT Cookie，也不要求401监控总开关开启；单独清理开关可关闭。
- 进程需运行、凭据库需解锁。服务锁定时不会执行真实云端操作。

## API

- `/api/state` 增加 `retirement` 配置/运行状态及每账号 `retirement` 摘要。
- `POST /api/retirement/config`：`{"enabled":true,"group_id":null,"confirm_transfer":true,"connection_revision":"当前连接修订"}`（null=精确自动匹配）或显式组ID。
- `POST /api/retirement/check`：立即扫描并排队；返回排队不代表清理完成。

配置需要本地会话与解锁。所有云端操作保留原站点及账号ID校验。
