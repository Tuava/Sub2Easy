# v0.4.1 · 同一页导入并上线

## 不再切页

在“批量导入”页即可完成：

1. 选择 TXT 三段材料或 sub2api JSON，粘贴/上传文件。
2. 右侧显示已保存站点、模板、隔离组、生产组、代理等信息；可以展开“修改本次模板配置”在原页改组和保存。
3. 填写验号模型，确认服务器写入与隔离条件。
4. 点击主按钮 **“导入到服务器并上线”**。程序保存本批本地材料并创建服务器任务，不需要去号池再次勾选。
5. 原页下方的“本批导入进度”显示每项的服务器 ID、阶段与结果，可停止、刷新或重试失败项。

**“仅保存到本地”是次要选项**，不会创建服务器任务。既有号池的部署入口仍保留，便于以后操作本地库存；不是本次导入的必经路径。

## 后端合同

`POST /api/import/deploy` 一次接收材料、格式、模板、站点连接修订、模型、确认与 request_id；在本地事务中完成校验、材料入库、逐号部署入队、批次报告保存。事务里不发上游网络请求，只有提交后 Worker 才开始授权和写云端。

输入的有效项与本地 ID 对应关系来自导入结果本身，不通过“导入前后全库 diff”推断，避免把另一个页面新增的账号误加入本批。相同账号可复用已有材料；材料冲突项不会拿库里的另一份密码继续部署。

相同 request_id 与相同请求内容重放返回原批次当前进度，不再建任务；相同 ID 但不同内容拒绝。输入内容只保留带密钥 HMAC 摘要用于幂等比较，不额外保存一份明文文本。即使批内部分失败，所有有效项仍在同一响应里说明。

`GET /api/import/batch` 返回当前站点最近一次批次，也可指定 request_id。按批次关联的任务 ID 获取实时结果，不受“最近200条任务”分页影响。刷新页面、离开再回来仍能看到本批。

`POST /api/import/batch/:id/retry` 只重试明确失败/取消且材料已接受的条目，沿用原模板和部署检查点。未知创建/写入、格式/身份冲突仍不盲目重放。显示“排队中”不等于云端已上线，只有最终任务成功才标“已在服务器上线”。

## 本轮验证

- 单页动态交互：不选择号池、不调用两段式保存API、不切页；同页模板编辑、失败保留文本、网络断开后相同提交ID重试。
- API：TXT/JSON一请求入库并入队、批内坏行、材料冲突、重复提交、站点变化、事务异常回滚、批次实时进度、单项重试。
- 本地真实HTTP模拟：通过这个新入口直接导入Token-only JSON，完成创建、暂停、SSE验号、生产组更新、再次验号、启用，最后批次显示服务器ID和 succeeded。
- 没有为了验证而将用户尚未选择的新账号导入生产站点。

## v0.5.2 · 失败预检查的模板同步

修复重新提交时批次展示新模板、旧 deployment 检查点却继续使用旧模板的错配。仅当新账号停在分组/代理校验失败，且没有绑定、云端ID、授权尝试或写入意图时，使用本次明确提交的模板替换旧快照。保留旧模板摘要用于对账。已经开始授权或创建账号的续跑不替换模板。

当前站点最近批次若符合上述条件，解锁后自动按该批次的模板重新排队；不拿全局新设置静默覆盖其他批次。界面显示每项实际执行的模板版本、分组和代理，以及本次预检查确实未找到的ID。
